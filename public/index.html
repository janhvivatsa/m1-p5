College Viva & Evaluation Guide

Architectural Design: Hallucination-Aware Information Assistant

This application implements a two-stage generative and verification architecture powered by DeepSeek AI, specifically built to combat the critical vulnerability of Large Language Model (LLM) overconfidence and ungrounded factual fabrication.

⚡

1. Two-Stage AI Verification Pipeline

Standard LLMs often generate hallucinations with high stylistic fluency and unwavering confidence. To address this:

  • Stage 1 (Generation): DeepSeek produces an initial comprehensive answer to the user's prompt based on the question and optional reference context.
  • Stage 2 (Independent Audit): An isolated, highly critical reviewer prompt acts as an adversarial fact-checker. It deconstructs the answer into atomic propositions and audits each claim independently.
🏷️

2. Three-Tier Claim Classification

Every extracted factual statement is classified into one of three strict heuristic categories:

  • High Confidence (80–100%): Explicitly substantiated by user-supplied reference material or universally verified scientific/historical facts.
  • Inferred (50–79%): Logically deduced from available context but without direct verbatim citation.
  • Potentially Hallucinated (0–49%): Lacks empirical backing, contains overly specific unverified dates/names, or risks fabrication.
⚖️

3. Confidence vs. Factual Accuracy

A core principle emphasized in this project: AI confidence does not equal factual truth.

  • Probabilistic language models predict plausible text sequences, not factual correctness.
  • Confidence scores displayed in this tool are heuristic indicators reflecting evidentiary support, not uncalibrated internal softmax probabilities.
  • When evidence is absent, the system explicitly marks claims as requiring external verification.
🔌

4. DeepSeek API Implementation

Technical implementation details for review:

  • Backend: Node.js and Express.js proxying requests securely to https://api.deepseek.com/chat/completions.
  • Model: deepseek-chat with strict JSON extraction and schema validation.
  • Security: The API key remains safely on the backend and is never exposed to client-side code.
  • Storage: Zero external database dependencies; browser LocalStorage manages history and user feedback.

Key Viva Questions & Answers

Q: What causes hallucinations in Large Language Models?
A: LLMs are trained to minimize cross-entropy loss over text tokens. They do not possess an internal world model or a verified relational database of truth. When knowledge gaps or probabilistic ambiguity arise, the model generates statistically plausible yet factually incorrect tokens.
Q: Why did you implement a two-stage prompt architecture rather than a single-prompt answer?
A: In a single prompt, the model suffers from confirmation bias—it defends the claims it just generated. By separating answer generation from claim deconstruction and fact-checking, Stage 2 critically interrogates each proposition without assuming innocence.
Q: How does user feedback and reanalysis work?
A: Users can validate or challenge claims. When a user provides reference documentation, the reanalysis endpoint re-submits the answer and new evidence to DeepSeek, dynamically updating confidence scores.
